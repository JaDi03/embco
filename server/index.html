    Run your own server¶

    This guide sets up what runs behind app.embco.xyz on a server of your own: the dashboard, the hub (the API the dashboard uses to connect shops) and one agent per shop. Shop owners then use your dashboard exactly as they use app.embco.xyz: they create their shop contract, connect their ERPNext and set their limits there.

    What you need

    • A server with Ubuntu or Debian (tested on Ubuntu 24.04), and a user with sudo.
    • A domain pointing to the server, with ports 80 and 443 open. The dashboard gets its HTTPS certificate on its own.
    • A Circle account with developer-controlled wallets: an API key and a registered entity secret.
    • An Anthropic API key, for the AI model that decides.
    • An Arc Testnet node URL.
    • Optional: a Telegram bot token from @BotFather.

    Install¶

    git clone https://github.com/JaDi03/embco.git
cd embco
cp .env.example .env
nano .env
sudo bash deploy/install.sh

    In .env, write your domain in EMBCO_SITE and fill in the node URL and the keys. Each line has a short note.

    The script checks .env before it installs anything, and says what is missing. It ends with Done. Open https://your-domain: open it, and the dashboard asks to connect a wallet. From there, shop owners follow Connect your ERPNext.

    Save the shop key

    The script creates /etc/embco/shops.key, which encrypts each shop's connection on disk. Save a copy now, apart from any other backup, as below.

    Update or change a setting¶

    The same command, from the same folder, updates everything and keeps your settings:

    cd embco
sudo bash deploy/install.sh

    The script moves .env to /etc/embco/embco.env, so no copy with your keys stays in the folder you cloned. To change a setting, edit that file, or write a new .env in the folder, and run the command again.

    Back up and move to a new server¶

    Moving the shops to a new server takes two things, kept in different places so that neither one alone is of any use:

    1. The shop key. It never changes, so you save it once, in a password manager:

      sudo cat /etc/embco/shops.key

    2. The shops' data (settings, connection and journal), backed up as often as you like, with the agents stopped for a moment so the journals are complete:

      sudo systemctl stop 'embco-shop@*'
sudo tar czf embco-shops.tar.gz /var/lib/embco/shops
sudo systemctl restart embco-hub

      Restarting the hub starts the agents again. Keep the file off the server.

    On the new server, put both back before you install, then install as usual:

    sudo install -d -m 700 /etc/embco
sudo nano /etc/embco/shops.key            # paste the key from your password manager
sudo tar xzf embco-shops.tar.gz -C /
git clone https://github.com/JaDi03/embco.git
cd embco
cp .env.example .env
nano .env
sudo bash deploy/install.sh

    The script keeps the restored key, gives the files to the embco user, and the hub starts the agents of the shops whose owners left them on. Point your domain to the new server first.

    What the script sets up¶

    What Where
    The code, run by its own system user embco, which can only write its own data /opt/embco
    The server's settings and the shop key, readable only by root and embco /etc/embco
    Each shop's settings, ERPNext keys (encrypted) and journal /var/lib/embco/shops
    The hub, the Telegram bot and one agent per shop, restarted if they stop systemd: embco-hub, embco-telegram, embco-shop@<contract address>
    Automatic source verification, independent of shop agents and ERP connections systemd: embco-verification.timer; state in /var/lib/embco/verification
    A rule that lets the hub start, stop and restart the shops' agents, and nothing else polkit
    The dashboard with HTTPS, /api to the hub and /rpc to your Arc node, whose URL stays on the server Caddy

    The hub starts a shop's agent when its owner connects ERPNext in the dashboard. If Caddy already serves other sites on the server, the script adds the dashboard next to them.

    Logs¶

    journalctl -u embco-hub -f
journalctl -u 'embco-shop@*' -f

    Contract verification¶

    The installer enables embco-verification.timer. It runs one bounded round after boot and one minute after the previous round finishes. New and existing contracts created by the configured factories are discovered on chain, even if their owners have not connected ERPNext. The service only reads the chain and submits public source code; it cannot sign transactions.

    The Arc node uses ARC_TESTNET_RPC_URL. Funding discovery uses public Base Sepolia and Ethereum Sepolia nodes, with optional BASE_SEPOLIA_RPC_URL and ETHEREUM_SEPOLIA_RPC_URL overrides in /etc/embco/embco.env. The worker checks each node's chain ID before scanning.

    systemctl status embco-verification.timer
journalctl -u embco-verification.service -n 50
sudo -u embco /opt/embco/.venv/bin/python -m services.verification --status

    Status reports discovered contracts, exact Sourcify matches, contracts the explorer showed or accepted for import, and contracts still pending on Sourcify. A submitted job is not counted as verified until Sourcify confirms an exact match. Pending jobs, last errors, frozen factory compilations and scan positions are stored in /var/lib/embco/verification/state.sqlite3. Back up that directory to preserve progress; without it, the worker rescans and checks the contracts again without redeploying anything. Do not run a second worker manually while the timer's service is active.

    To inspect discovery without submitting source code, use a separate local state file:

    python -m services.verification --env-file .env --state verification.sqlite3 --discover-only
python -m services.verification --state verification.sqlite3 --status

    The factories must already have an exact runtime match on Sourcify, with their compilation input and deployment block available. A future factory release needs that verification first. Factory packages are cached after the first successful lookup. The worker respects provider cooldowns and retries transient failures; repeated source mismatches need operator review.
